# Reglas de Competencia — Claude Impact Lab Chile 2026 

Estamos construyendo para una competencia de impacto cívico. Estas reglas guían las decisiones de diseño y priorización.

## Prioridades

1. **Demo funcional** sobre features incompletas. Mejor un flujo completo simple que muchos flujos rotos.
2. **Impacto ciudadano visible** sobre complejidad técnica oculta.
3. **Claude como motor central** — la demo debe mostrar claramente que Claude hace el trabajo inteligente.
4. **Cuidar PII** — nunca mostrar datos del usuario en la demo sin consentimiento explícito.
5. **Accesibilidad real** — la demo debe ser usable por alguien con poca experiencia digital.

## Lo que NO hacer

- No inventar datos regulatorios, leyes ni procedimientos chilenos.
- No construir features que no aporten al flujo principal de la demo.
- No usar datos reales de personas en demos o tests.
- No hacer push de secretos al repositorio.

## El flujo de demo principal

```
Usuario describe fraude → Claude clasifica → Acciones urgentes → Expediente preliminar
```

Este flujo debe funcionar de punta a punta antes de agregar cualquier otra feature.

## Recordatorio de criterios de evaluación

- Uso real y demostrativo de Claude
- Impacto cívico medible o argumentado
- Datos responsables y privacidad
- Accesibilidad e inclusión
- Viabilidad técnica del demo
